1) PROJECT OVERVIEW
====================================================================

Project summary:
This project is an AI-assisted real-estate intelligence and comparison platform.
It aggregates listings from multiple real-estate websites, enriches listings with
computer-vision and geospatial signals, and provides both classic and agentic
decision support. It also supports visual search (search by room photo) using
image embeddings and vector similarity.

Core user capabilities:
- Search listings by location, property type, listing type, and BHK.
- Compare results with map markers and card-based ranking.
- Analyze image-based property condition (modernity, wear/tear, lighting).
- Analyze location quality (greenery index, traffic congestion index).
- Run agentic evaluations (fair value, forecast, fraud risk, sentiment,
  negotiation draft, confidence summary).
- Search similar properties by uploading an image.
- Index properties into a vector store for visual retrieval.

5) APPLICATION ARCHITECTURE
====================================================================

Layer 1: Listing acquisition and normalization
- Multi-query SerpAPI search for listing snippets across domains.
- Price extraction and normalization (INR formats: Cr, Lac, K, raw numeric).
- Deduplication by canonical URL.
- Listing-type filtering (buy/rent/pg) and unrealistic price filtering.

Layer 2: Enrichment
- Geocoding and coordinate scattering for map display.
- Image scraping/download and condition scoring.
- Satellite + roadmap tile analysis for greenery/traffic metrics.

Layer 3: Agentic analysis
- Goal planner produces task DAG.
- Property-level orchestrator computes valuation, forecast, fraud clusters,
  defects, sentiment, negotiation draft, and confidence metadata.
- Strict mode can suppress low-confidence agentic evaluations.

Layer 4: Retrieval and vector infrastructure
- Image embeddings generated via CLIP model.
- Local vector store supports cosine similarity retrieval.
- Optional Pinecone adapter for remote vector DB usage.
- Multimodal RAG module supports text + image weighted retrieval.

Layer 5: UI delivery
- Homepage search + upload CTA.
- Results page with map/list and rich property cards.
- Image similarity results page with match statistics.

7) COMPLETE API DOCUMENTATION
====================================================================

A) Core APIs

1) GET /api/search
Purpose:
- Main listing discovery and enrichment endpoint.

Query params:
- location (required)
- propertyType (optional; default apartment)
- listingType (optional; default rent; buy/rent/pg)
- bhk (optional; default any)
- strictAgentic (optional)

Behavior:
- Calls searchProperties + geocodeLocation in parallel.
- Scatters marker coordinates.
- For each property:
  - analyzeLocation (3s timeout)
  - scoreProperty/images (5s timeout)
  - runAgenticEvaluation (2.5s timeout)
- Returns best-effort enriched output.

Response shape:
- results: Property[]
- total: number
- query: object
- center: object|null

2) POST /api/search-similar
Purpose:
- Find visually similar properties from vector store.

Input:
- multipart/form-data with image
- Query params: topK (1..100), threshold (0..1)

Behavior:
- Validates image type and <=10MB
- Creates embedding
- Runs cosine similarity search against stored vectors

Output:
- results with similarity and property metadata
- stats object (matches, top/avg similarity, dimensions)

3) GET /api/search-similar
Purpose:
- Returns vector store status and statistics.

4) POST /api/embed-image
Purpose:
- Embed one uploaded image and return vector dimensions and metadata.

Input:
- multipart/form-data with image

5) POST /api/index-properties
Purpose:
- Batch indexing pipeline for visual search corpus population.

Input body:
- location (required)
- propertyType, listingType, bhk (optional)
- limit (optional, capped to 100)

Behavior:
- Fetch listings, scrape images, generate embeddings, add to vector store.
- Includes per-property failure collection.

Output:
- success/indexed/total/failureCount/message.

6) GET /api/index-properties?action=status
Purpose:
- Vector store status for indexing workflow.

7) GET /api/score-property
Purpose:
- Score listing images from property URL.

Query params:
- url (required)

8) GET /api/analyze-location
Purpose:
- Compute greenery and traffic indices from lat/lng.

Query params:
- lat, lng (required)

B) Agentic APIs

9) POST /api/agentic/plan
- Input: UserGoalInput with goal string
- Output: normalized goal and task plan DAG

10) POST /api/agentic/evaluate
- Input: goal, property, optional peers
- Output: planner + full agentic evaluation payload

11) GET /api/agentic/scrape
- Input: url query
- Output: extracted fields via heuristic or llm-assisted mode

12) GET /api/agentic/sentiment
- Input: query text
- Output: sentiment score, confidence, highlights, sources

13) POST /api/agentic/stage-room
- Input: imageUrl/prompt/style/roomType
- Output: generated/simulated staging response

14) POST /api/agentic/rag/query
- Input: multipart (query, optional docs, optional image)
- Output: multimodal retrieval results + indexed count

15) POST /api/agentic/vector/upsert
- Input: vector records array
- Output: upsert success metadata

16) POST /api/agentic/vector/query
- Input: query vector, optional topK
- Output: query result list

17) POST /api/agentic/graph/sync
- Input: nodes and edges arrays
- Output: neo4j sync status

18) POST /api/agentic/workflow/run
- Input: goals[] + listings[]
- Output: top recommendation per goal

8) CORE LIBRARY MODULES AND IMPLEMENTATION DETAILS
====================================================================

1. src/lib/serpapi.ts
- Defines Property and SearchParams interfaces.
- Builds multiple search queries to improve coverage and precision.
- Filters aggregate pages and non-matching listing types.
- Price normalization handles Cr/Lac/K and raw values.
- Deduplicates by normalized URL.
- Sorts results by ascending price.

2. src/lib/geocode.ts
- Geocodes location using OSM Nominatim.
- Adds scatter offsets to avoid marker overlap in maps.

3. src/lib/imageScraper.ts
- Scrapes listing HTML for likely property images via selector sets.
- Downloads images with request limits and safeguards.

4. src/lib/imageScoring.ts
- Computes image statistics from raw pixels.
- Produces four scores:
  - modernity
  - wearAndTear
  - lighting
  - overall
- Uses heuristic CV scoring with fallback neutral scores on error.

5. src/lib/satelliteImagery.ts
- Fetches ESRI satellite and OSM roadmap tiles at zoom 17.

6. src/lib/satelliteAnalysis.ts
- Greenery estimation by vegetation pixel logic.
- Traffic estimation from road/highway/connectivity heuristics.
- Returns normalized 0..100 indices.

7. src/lib/imageEmbeddings.ts
- Loads CLIP model from transformers runtime.
- Preprocesses image to 224x224.
- Generates embedding vectors and normalizes for cosine search.
- Uses caching utilities to reduce repeated inference.

8. src/lib/embeddingCache.ts
- Stores embeddings by hash in .embedding-cache.
- TTL-based staleness handling (30 days).

9. src/lib/vectorStore.ts
- File-based store operations:
  - load/save
  - add/batch add
  - cosine search
  - stats/clear
- Backing file: public/vector-store.json.

9) AGENTIC SUBSYSTEM - COMPLETE BREAKDOWN
====================================================================

1. types.ts
- Defines all agent interfaces and data contracts:
  - tasks, planner output
  - valuation input/output
  - forecast input/output
  - fraud nodes/clusters
  - negotiation payloads
  - sentiment payload
  - final AgenticEvaluation schema

2. planner.ts
- Converts user goal into 8-task plan:
  search -> vision -> sentiment -> valuation -> risk -> forecast -> negotiate -> report
- Encodes task dependencies.

3. orchestrator.ts
- End-to-end per-property evaluation pipeline:
  - sentiment fetch/scoring
  - comparable extraction
  - fair value estimation
  - forecast projection
  - fraud cluster detection
  - defect derivation
  - negotiation draft
  - recommendation and confidence signals
- Computes strict-check failures for confidence gating.

4. valuation.ts
- Rule/feature-contribution fair-value surrogate model.
- Uses location, condition, greenery, traffic, sentiment, infra, area.
- Optionally blends comparable median when enough peers exist.

5. forecast.ts
- Surrogate forecasting over 1..24 months.
- Monthly drift includes base growth + repo + infra + sentiment terms.
- Adds seasonality and outputs projected return percent.

6. fraudGraph.ts
- Builds graph edges based on fraud evidence:
  - shared phone
  - shared image hash
  - high text similarity
  - significant same-locality price variance
- Creates connected components and risk scores.

7. sentiment.ts
- Pulls Reddit snippets and scores lexical polarity.
- Returns score, confidence, highlights, and source list.

8. negotiator.ts
- Calculates discount from overpricing + defect penalties.
- Generates email subject/body and counter-offer price.

9. scraper.ts
- Fetches arbitrary page and extracts structured fields.
- Modes:
  - behavioral-fetch + heuristic parsing
  - llm-assisted extraction (if OPENAI_API_KEY set)

10. rag.ts
- In-memory document indexing.
- Multimodal retrieval score:
  score = lexical * 0.55 + visual * 0.45
- Supports optional image-conditioned retrieval.

11. workflow.ts
- Proactive multi-goal evaluation over listing sets.
- Picks top listing per goal via composite score using fair value delta,
  forecast return, and fraud risk.

12. neo4j.ts
- Optional graph sync to Neo4j HTTP endpoint.
- Upserts nodes and edges via Cypher statements.

13. vectorDb.ts
- Adapter interface for vector providers.
- Pinecone implementation + default no-op fallback.

14. virtualStaging.ts
- Optional Stability API room staging.
- Graceful fallback to simulated output when key missing.

15. propertyAnalyzer.ts
- Extracts semantic features from property descriptions for indexing context.

14) RUNTIME SAFEGUARDS, TIMEOUTS, AND FALLBACKS
====================================================================

Timeouts:
- /api/search route maxDuration: 300s
- /api/embed-image maxDuration: 120s
- /api/search-similar maxDuration: 120s
- /api/index-properties maxDuration: 600s
- /api/agentic/rag/query maxDuration: 120s

Per-task defensive timeouts in /api/search:
- location analysis timeout per property: ~3s
- image scoring timeout per property: ~5s
- agentic evaluation timeout per property: ~2.5s

Fallback behavior examples:
- If image scoring fails -> neutral/default scores or null score
- If satellite analysis fails -> neutral location indices
- If optional providers not configured (Neo4j/Pinecone/Stability/OpenAI)
  -> modules degrade gracefully or return simulated/empty responses
- strictAgentic mode can hide low-confidence evaluations
